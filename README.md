# elmtrapp

تطبيق ويب عربي RTL لإدارة مكتب المحاماة، مبني بـ Next.js App Router وTypeScript وSupabase. تصميم فاتح وداكن متجاوب مع الموبايل والتابلت والكمبيوتر.

## صفحات الموقع والتسعير

- `/`: اللاندنج بيدج العامة.
- `/demo`: حساب ديمو مستقل ببيانات محلية، بدون بريد أو كلمة مرور مشتركة؛ يبقى وضع الديمو عند التنقل داخل نفس تبويب المتصفح.
- `/dashboard`: لوحة المكتب، وتتطلب تسجيل الدخول للحساب الحقيقي.
- `/login`: تسجيل الدخول؛ `/login?mode=signup` لإنشاء حساب. الدخول إليها ينهي وضع الديمو.

التسعير موحد في `src/lib/pricing.ts`: تفعيل الأساسي **2800 جنيه مرة واحدة**، والبرو إضافة اختيارية **250 جنيه شهريًا** أو **2000 جنيه سنويًا بدل 3000**. لا توجد عملية تحصيل إلكتروني أو تفعيل اشتراك تلقائي.

## التشغيل

يتطلب Node.js 22 أو أحدث.

```bash
npm ci
npm run dev
```

افتح `http://localhost:3000`. بدون إعداد Supabase يعمل وضع المعاينة: بيانات تجريبية محفوظة محليًا في المتصفح، ومستندات داخل IndexedDB. لا تُستخدم البيانات التجريبية تلقائيًا في الحساب الحقيقي.

## ربط Supabase — يدويًا

1. أنشئ مشروع Supabase.
2. انسخ **كل محتوى `supabase/setup.sql`** وشغّله مرة واحدة في SQL Editor بحساب مالك المشروع. الملف مجمّع وقابل لإعادة التشغيل على نفس مخطط التطبيق.
3. انسخ `.env.example` إلى `.env.local` وأضف:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

4. من Authentication → URL Configuration اضبط Site URL على رابط الموقع، وأضف localhost للتطوير. اضبط إعدادات تأكيد البريد وSMTP بحسب حسابك.
5. أعد تشغيل التطبيق، وأنشئ حسابًا من صفحة الدخول. إذا كان تأكيد البريد مفعّلًا، افتح رسالة التأكيد ثم سجل الدخول. لا توجد كلمات مرور افتراضية.
6. عند النشر، أضف نفس متغيرات البيئة على منصة الاستضافة ثم أعد البناء.

لا تستخدم `service_role` أو مفاتيح Supabase السرية داخل `NEXT_PUBLIC_*`؛ التطبيق كله يستخدم هوية المستخدم وسياسات RLS.

## الشاشات والعمليات

- نظرة عامة بإحصاءات محسوبة من بيانات الحساب، وجلسات قادمة وقضايا حديثة.
- إنشاء وتعديل القضايا، حالات القضية، بحث بالعنوان والرقم والعميل.
- ملف القضية: التفاصيل والخصم والملخص والملاحظات والجلسات والمستندات.
- العملاء: إنشاء وتعديل بيانات الاتصال والعنوان والرصيد السابق.
- حساب العميل: مجموع الرصيد السابق + أتعاب كل القضايا، ثم خصم دفعات العميل. الدفعة **على الحساب** ولا تُربط بقضية منفردة. تعديل الدفعات وحذفها يعيد حساب المتبقي.
- تقويم شهري وجلسات، وتصدير ICS يتضمن تذكيرًا إلى تقويم الجهاز. إشعارات الأسبوع داخل التطبيق ليست خدمة Push في الخلفية.
- رفع PDF / JPG / PNG / WebP بحد أقصى 20 MB. الملفات السحابية خاصة وتُفتح عبر رابط موقع مؤقت لمدة 60 ثانية.
- ماسح الكاميرا والمعرض: اقتراح حدود ورقة فاتحة اللون على خلفية متباينة، ضبط قص يدوي، تدوير، تحسين التباين، وتجميع صفحات في PDF. يعمل التصوير على HTTPS أو localhost مع إذن الكاميرا. تصحيح المنظور وOCR التلقائي غير مشمولين؛ يمكن إدخال نص المستند يدويًا للتحليل.
- مرجع القانون: بحث بنص القانون/اسم القانون/رقم المادة، مصادر المواد وتواريخ مراجعتها، ومحفوظات.
- مساعد قانوني مرتبط بالقضية، ملخصها وملاحظاتها والنصوص المدخلة للمستندات؛ تحقق من صلاحية الحساب والاشتراك على الخادم.
- الإعدادات: اسم المحامي والمكتب والهاتف والمظهر وحالة الباقة. ملف manifest يتيح الإضافة للشاشة الرئيسية؛ الحساب السحابي يتطلب الإنترنت ولا توجد مزامنة Offline.

## تفعيل الاشتراك

الأساسية تشمل عمليات المكتب. مرجع القانون والـAI يتطلبان اشتراكًا ساريًا في قاعدة البيانات، لا مجرد إخفاء بالواجهة. لا يستطيع المستخدم تغيير باقته بنفسه.

نفّذ **من SQL Editor كمالك** مع UUID المستخدم من Authentication → Users:

```sql
insert into public.entitlements(owner_id, plan, expires_at)
values ('REPLACE_WITH_AUTH_USER_UUID', 'monthly', now() + interval '1 month')
on conflict (owner_id)
do update set plan = excluded.plan, expires_at = excluded.expires_at;
```

للسنوي استخدم `annual` و`interval '1 year'`. للإيقاف: `update public.entitlements set plan='basic', expires_at=null where owner_id='UUID';`. لا توجد بوابة دفع أو تجديد اشتراك تلقائي في هذا التنفيذ.

## إضافة المرجع القانوني

الملف لا يضيف نصوصًا قانونية مختلقة أو غير متحقق منها. أضف قوانين فعلية مرخصة الاستخدام ومراجعة عبر SQL Editor أو استيراد CSV إلى `laws` ثم `articles`:

- `laws`: `title`, `number`, `year`, `source_url`, `verified_at`.
- `articles`: `law_id`, `article_number`, `chapter`, `body`, `source_url`, `verified_at`.

المراجع مشتركة للمشتركين فقط، وتعديلها محصور بمالك قاعدة البيانات. يتطلب المساعد تاريخ مراجعة `verified_at` حتى يستشهد بالمادة. تحديث النصوص عند تعديل التشريعات مسؤولية إدارة المحتوى. واجهة المعاينة تعرض حالة المرجع الفارغ بوضوح.

## تشغيل المساعد

أضف **على الخادم فقط**:

```dotenv
AI_GATEWAY_API_KEY=YOUR_GATEWAY_KEY
AI_MODEL=provider/model-id
```

اختر معرف موديل حالي يدعم توليد النص من قائمة `https://ai-gateway.vercel.sh/v1/models`. لا يوجد معرف موديل قديم مفروض في الكود. مزود الـAI وتكلفته منفصلان عن Supabase.

كل طلب يمر بتسجيل الدخول، وصلاحية الوصول للقضية، والاشتراك، ثم حد استخدام محفوظ في Postgres: **10 طلبات/دقيقة و300 طلب/شهر تقويمي UTC**. تُحسب محاولة الإرسال حتى لو فشل المزود لاحقًا. المساعد يرسل ملخص القضية وملاحظاتها والنصوص المدخلة للوثائق؛ لا يرسل صور المستندات تلقائيًا ولا يدّعي قراءتها. يذكر مصادر المواد المطابقة من المرجع ويصرح بعدم توفر مصدر عند غيابه. الديمو يعرض محاكاة توضيحية معلنة وقائمة مراجعة محلية؛ لا يقدم رأيًا قانونيًا أو تحليل AI فعليًا.

## قاعدة البيانات

`supabase/setup.sql` يشمل كل الجداول والفهارس وRLS وStorage والسياسات والدوال وحسابات العملاء. كل حساب مكتب مستقل؛ الربط بين الجداول يتحقق من `owner_id` أيضًا. الاشتراكات والأسعار يغيرها الأدمن وحده، والمرجع للقراءة من التطبيق. حاوية المستندات خاصة. الحماية المالية داخل قاعدة البيانات تمنع تجاوز المتبقي وتمنع تخفيض الأتعاب عن المدفوع، مع قفل سجل العميل لتسلسل العمليات المتزامنة.

الدالة الخاصة `private.consume_ai_slot` تعمل بصلاحية مالكها فقط لكتابة سجل معدل الاستخدام غير المكشوف؛ تتحقق من `auth.uid()` والاشتراك داخليًا. لا توجد دوال صلاحيات عامة تتجاوز ملكية القضية.

## التحقق

```bash
npm run typecheck
npm run lint
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

اختبار SQL ينفذ نفس الملف مرتين على PostgreSQL مضمّن (PGlite) مع محاكاة مخططي Auth وStorage، ويتحقق من عزل المستخدمين والدفعات والاشتراكات وسياسات الملفات. اختبارات المتصفح تغطي الشاشات على 320 و390 و768 و1440 px، والمظهر الداكن، وإنشاء عميل وقضية وتسجيل وتعديل دفعة وحفظ المستندات. يمكن ضبط `BROWSER_EXECUTABLE_PATH` لاستخدام Chromium مثبت محليًا.

يلزم اختبار اتصال Auth وStorage الحقيقي بعد تشغيل SQL وربط مشروع Supabase؛ راجع نتيجة تطبيق SQL على مشروع Supabase المرتبط عند النشر.


## هوية Elmtr App وفريق المكتب

الأسعار العامة تقرأ من `site_prices`؛ القيم الأولية2800 للنظام،250 شهريًا و2000 سنويًا للبرو، و50 شهريًا أو600 سنويًا للحساب الفرعي. بعد تسجيل وتأكيد حساب الأدمن، ينفذ مالك مشروع Supabase مرة واحدة في SQL Editor (استبدل البريد):

```sql
insert into private.site_admins(user_id)
select id from auth.users where lower(email)=lower('YOUR-ADMIN-EMAIL');
```

تظهر لوحة الأدمن داخل الإعدادات لتغيير الأسعار وتفعيل البرو وعدد الحسابات الفرعية ومدة التفعيل وسعر المكتب. لا يوجد تحصيل إلكتروني تلقائي. يسجل المحامي الفرعي حسابه ويؤكد البريد ثم يضيفه صاحب المكتب بالبريد والاسم والصلاحيات. القراءة والكتابة والوصول للمستندات تتحقق من قاعدة البيانات؛ انتهاء التفعيل يسحب الوصول. الأقسام المترابطة تحتاج صلاحياتها معًا (مثلاً الحسابات تحتاج العملاء والقضايا والمدفوعات).

مستند العميل يرتبط بـ `client_id` وحده، ومستند القضية بـ `case_id` وحده. مقتطف المرجع هو المواد2–4 من القانون المدني131/1948 مع رابط الوثيقة الأصلية، وليس موسوعة شاملة أو ضمانًا لآخر التعديلات.

PWA: التثبيت من الإعدادات أو قائمة المتصفح. Service Worker يحفظ صفحة عامة لحالة انقطاع الاتصال فقط؛ لا يحفظ ملفات العملاء أو ردود API. `supabase/setup.sql` هو الملف المجمع الكامل؛ `upgrade-office.sql` ترقية المشاريع التي لديها المخطط السابق بالفعل.


## إدارة المنصة وطلبات التفعيل

`/admin` لوحة مستقلة للأدمن؛ الدخول بحساب أدمن يفتحها مباشرة. تعرض جميع حسابات Auth حتى قبل استكمال بيانات المكتب، مع البريد وتأكيده وتاريخ التسجيل وحالة النظام والبرو. إنشاء حساب جديد ينشئ Profile وطلب تفعيل تلقائيًا بواسطة trigger على Auth. لا يدخل المكتب قبل موافقة الأدمن، وتُفرض الحالة داخل RLS وStorage. تعرض اللوحة الطلبات وتحدثها كل30ثانية وعند الرجوع للصفحة.

من الحساب يمكن تفعيل النظام أو إيقافه، وتفعيل البرو شهرًا تقويميًا أو سنة من وقت الموافقة، أو إلغاؤه. طلبات البرو من إعدادات العميل لا تفعل الاشتراك ذاتيًا. الموافقة تسجل صاحب القرار ووقته وتمنع إعادة معالجة الطلب نفسه. تأكيد البريد مطلوب قبل التفعيل. مكاتب قائمة لديها عملاء قبل الترقية تحتفظ بتفعيلها؛ التسجيلات الجديدة تبدأ معلقة. `upgrade-admin.sql` لترقية المخطط السابق، و`setup.sql` يشمل كل شيء.
